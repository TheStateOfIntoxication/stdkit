# 0001 跨文件确定性层：只做两条，其余留语义层

## 状态

已采纳（部分实现：`SQL-RBK-01`、`SQL-DIA-01` 做成 `ds cross`，其余不做）。

## 背景与问题

现有 48 条 `deny` 全是**单行形态**。而团队里代价最高的问题往往在**文件集合**层面：

- `SQL-RBK-01`：正向脚本有没有配同名回滚；
- `SQL-DIA-01`：L3 声明的每个方言目录是否都有同序号的变更；
- `J8-MBT-07`：改了 `mapper/mysql/*.xml` 有没有同步改 `mapper/postgres/*.xml`；
- `V2-API-05`：`.vue` 里直接调接口，而不是走 `api/` 目录。

这些现在都归「语义层交给模型」，但其实**可以机判**——判据不在单行文本里，而在文件清单里。

## 决策

**只实现两条**，作为 `ds cross` 命令（与 `ds scan` 分开，因为判定单位是文件集合而非行）：

| 检查 | 判据 | 为什么选它 |
|---|---|---|
| `SQL-RBK-01` | `sql/upgrade/<dialect>/00N_x.sql` 必须有 `rollback/00N_x.sql`（或 `sql/rollback/<dialect>/00N_x.sql`） | 目录约定明确、文件名规则稳定、误报几乎为零；缺回滚是真实事故源 |
| `SQL-DIA-01` | L3 `engines` 声明的每个方言目录都存在，且各目录的脚本序号集合一致 | 同上；且 `ds doctor` 已有雏形逻辑可复用 |

其余跨文件规则**不做**：

- `J8-MBT-07`（多方言 XML 同步）：需要判断两个 XML 是否「语义等价」，名字对不齐就算误报；
- `V2-API-05`（接口调用抽 `api/`）：要解析导入与导出关系，接近 AST 分析（见 ADR 0002 的同款理由）。

## 备选与为什么不选

1. **全部做成 `deny` 元数据的新键（如 `cross:`）** —— 会引入第二套规则格式，`parse/catalog/check/build`
   四处都要改，且 `deny` 的「行级」语义被稀释。改为**独立命令 + 复用已有规则 ID**，规则文件不动。
2. **放进 `ds scan` 内部** —— `scan` 的语义是「按行判、给行号」，跨文件检查没有单一行号可给
   （报告的是文件级问题），混在一起会让 `--diff`、`--limit`、baseline 行级豁免全部失去意义。
3. **全部十条跨文件规则一次做完** —— 误报风险高，一旦误报用户会连单行层一起关掉。

## 后果

**好处**

- 两条最容易出事、误报最低的检查变成 0 token 机判，`SQL-DIA-01` 是 `critical` 级；
- 规则文件不用改，`catalog` / `dist` 结构与既有豁免机制不受影响；
- 语义层清单少两条，模型注意力更集中。

**代价**

- 多一个命令（`ds cross`），用户要记「行级看 `scan`，文件级看 `cross`」；
- 目录约定写死在代码里（`upgrade/<dialect>/`、`rollback/`），命名不同的仓需要 `--layout` 参数
  或后续加配置；当前**只支持标准布局**，非标准布局会直接跳过（不误报）。

**触发复盘的条件**

1. 出现第三类「必须跨文件才能判」且误报可控的规则；
2. 有仓因为目录命名不同而无法使用（说明该支持配置化布局）；
3. `J8-MBT-07` 在多方言仓里连续两次漏掉同步（说明语义层兜不住）。
