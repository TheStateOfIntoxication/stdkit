# 0003 语义层回归不进 CI

## 状态

已采纳（推迟；用 prompt 一致性断言替代）。

## 背景与问题

79 条语义规则没有任何自动化信号，全靠人读条文。修改条文后，没人能保证模型还会照着审。

但「自动验证语义层」有两个硬约束：

1. **要跑模型**：验证「模型是否照表审、判级是否合理」必须调 LLM，结果不稳定（temperature、模型版本、
   prompt 位置都会影响），做成 CI 会引入 flaky。
2. **破坏离线可运行**：本仓的定位是「零依赖、可离线」。CI 里跑模型需要 API key 与网络，
   等于把「一个 `git clone` 就能用」变成「先配密钥」。

## 决策

**不做语义层的自动回归**，改为下面两层替代：

| 手段 | 保证什么 | 成本 |
|---|---|---|
| `ds check` 的 prompt ↔ catalog 断言 | prompt 里的 A/B 清单 == 该域规则全集；缺一条就报 error 并点名 | 0（已有） |
| `ds eval` 的覆盖率断言 | 每条**可机判**规则至少被一个用例命中 | 0（已有） |
| 人工审查 + `evals/cases` 攒误报样本 | 语义判定的质量 | 人力 |

也就是说：**「模型拿到的清单完整」是机器保证的**；「模型审得对不对」目前是人的责任。

## 备选与为什么不选

1. **`ds eval --semantic` 调模型跑一遍** —— 保留了自动化的可能性，但不进 CI，只在人工检查时手动跑。
   这是最接近可行的形态：`evals/semantic/<case>/diff.patch + expect-ids.json`，由人手动执行。
   留作 backlog（未实现）。
2. **用规则文本的 embedding / 关键词匹配来「验证」** —— 测的是措辞不是判定，只会制造虚假安全感。
3. **把语义规则全部改写成可机判** —— 相当一部分（事务边界、越权、幂等）本质需要跨文件与调用链上下文，
   硬写成正则就是造误报（见 `docs/limits.md` 的抓不到清单）。

## 后续（0.19.0 落地，不推翻上面的决策）

备选 1 的形态已经实现，并且**没有引入模型依赖**：`ds eval --semantic` 只做两件事——
校验 `evals/semantic/<case>/` 的结构（`mustReport` 必须是**没有 deny** 的语义规则），
以及比对「上一次人工/agent 审查的记录」`result.json`。记录由 `ds eval --record --reported --by` 写入，
谁审的、哪天审的都留在文件里。

于是 CI 仍然「不依赖模型与网络」（它只是在比对静态文件），而「换 prompt 后判定变了」这件事
第一次有了可比对的信号。代价照旧：**记录可以写错**，它证明的是「没变」，不是「对」。

## 后果

**好处**

- CI 不依赖模型与网络，任何环境 `git clone` 就能跑全绿；
- 失效模式被收窄到「清单完整」这一层，而这一层已经机判了；
- 不用为「模型版本升级导致回归」付维护成本。

**代价**

- 语义规则的真实有效性**没有数字**。条文写错、判级不合理，只能靠人在 review 中发现；
- 换模型或大改 prompt 时缺少回归网。

**触发复盘的条件**

1. **同一类语义漏审出现 ≥2 次**（这是本 ADR 的触发线，写进 backlog）；
2. 出现稳定的评测方式（如团队有固定模型与温度、且能容忍 ±1 的判定差异）；
3. 语义规则里出现「其实可机判但当时没写」的漏网项——那就把它降级成 `deny`，归入 `ds eval`。
