# 架构决策记录（ADR）

按「一个决策一份、只增不改」的方式记录**要不要做**、**为什么**、**代价是什么**。
改主意时新写一份并标 `替代 NNNN`，不回头改旧文件。

| 编号 | 决策 | 状态 |
|---|---|---|
| [0001](0001-cross-file-checks.md) | 跨文件确定性层：只做两条，其余留语义层 | 已采纳（部分实现） |
| [0002](0002-single-stack.md) | 不做 Vue 3 / TypeScript / JDK 17 规则域 | 已采纳 |
| [0003](0003-semantic-layer-regression.md) | 语义层回归不进 CI，先靠 prompt 一致性断言 | 已采纳（推迟） |
| [0004](0004-v1-freeze.md) | 1.0 冻结范围：只冻形状（catalog / policy / 退出码）+ 三条语义 | 已采纳 |
| [0005](0005-multi-version-rules.md) | 多版本规则：版本作为规则属性（J8/J17/J21 共用一套规则） | 提议（未实施） |

0001–0003 来自 `04-开发计划` 的 M4 战略项。共同判断标准：**这个功能会不会稀释「单栈可判」这个卖点**。
0004 来自 `docs/v1-freeze-review.md` 的冻结评估，回答的是另一个问题：**哪些东西一旦承诺就不能再改**。

写新 ADR 时用这个骨架（`check` 会校验这三节存在）：

```text
# NNNN 标题
## 状态        ← 提议 / 已采纳 / 已否决 / 被 NNNN 取代
## 背景与问题
## 决策
## 备选与为什么不选
## 后果（好处 / 代价 / 触发复盘的条件）
```
