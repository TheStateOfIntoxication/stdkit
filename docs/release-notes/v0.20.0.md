# stdkit v0.20.0

> **JDK 8 / Vue 2 / SQL 的工程规范与审查工具包**：规则写一次，Agent 产物全生成；能机判的一律机判。
> 这一版是 **1.0 的冻结基线**：catalog / policy / 退出码三处公开契约的形状从此由测试守住。

---

## 为什么需要它

团队里「代码该怎么写」通常散在 wiki、肌肉记忆、评审评论和几个 AI 指令文件里。这些内容有两个通病：
**会漂**（同一件事三处写得不一样，谁也不知道哪句最新）和**没法验**（写了「禁止 double 存金额」，
但除了盯着看没有任何东西保证它被遵守）。

stdkit 把这两件事交给机器：规则只有一份、每条有稳定编号；能机判的跑本机正则，判不了的才让模型读。
规则改一次，skills / prompts / adapters / AGENTS.md 四类产物一起重新生成，不用抄第二遍。

**127 条规则**，覆盖四个域：

| 域 | 条数 | 说明 |
|---|---|---|
| `java-jdk8` | 71 | JDK 8 语言、Spring Boot 2.x、MyBatis、工程实践 |

## 亮点

**1. 确定性层：49 条规则零 token 跑完**
`ds scan` 输出 `规则ID:行号`，可复现、可进 CI。命中片段默认**掩码**（`password=***`）——命中行往往就是密钥本身，
原样打印等于二次泄漏到 CI 日志与模型上下文。

**2. 仓级判定：`ds cross`**
单行正则判不了的问题放到文件集合层面：正向 SQL 脚本有没有同名回滚（`SQL-RBK-01`）、
L3 声明的引擎方言是否齐（`SQL-DIA-01`）。只认标准布局，非标准布局直接跳过，不误报。

**3. 计数型规则：`maxHits`（本版新增）**
有些规范的判据是**次数**而不是形态——「一个页面里 5 个以上原始请求就抽到 `api/`」。规则写
`deny` + `maxHits: 4` = 「允许 4 处，第 5 处起报」，且只报越线那一处。
`--diff` 模式下按整文件计数、只报落在改动内的越线行（否则「已有 4 处 + 新增 1 处」永远不报）。

**4. 语义层回归：`ds eval --semantic`（本版新增）**
不调模型、不联网：校验 `evals/semantic/<case>` 的结构（`mustReport` 必须是**没有 deny 的语义规则**），
再比对上一次人工/agent 审查的记录。改条文或 prompt 后重跑，判定变了就是信号。

**5. 发布脱敏：`ds publish-check --history`**
工作树干净 ≠ 历史干净——`force-push` 只改引用、不删对象。用它扫可达历史的**新增行**，
「已知且接受」的历史命中逐条枚举在 `policy/publish.json` 的 `historyAllow`（带 reason）。

**6. 一条命令装五端**
`ds install --all`：pi / Claude Code / Codex / Cursor / Copilot。一份 Node 实现 + 两个薄 shim，
Windows 与 *nix 行为一致；`--uninstall` 只删自己写过的文件（按 manifest）。

**7. 写前护栏（pi 扩展）**
`write` / `edit` 命中 critical 级规则时直接拦下，与 `ds scan` 共用同一份判定核心（不存在第二套实现）。

## 1.0 冻结基线

这一版的重点不是加功能，而是**把「以后不能再改」的东西钉住**：

| 契约 | 冻结方式 |
|---|---|
| `catalog/rules.json` | 新增 `schema: 1`（数据格式版本），与 `version`（产品版本）分开；形状由 `policy/compat.json` + `compat.test.mjs` 锁住 |
| `policy/*.json` | 三层各有**键白名单**，写错键直接报错（拼错的键是「配了但没生效」的经典来源） |
| 退出码 | **0 通过 / 1 有阻断 / 2 用法或环境错误**——CI 能区分「代码有问题」与「命令写错了」 |
| 三条语义 | 阈值语义（不是精确集合）、policy 浅合并、`applies` 相对业务仓根 |

破坏性变更会让 `npm test` 红，报错里直接给出三步升级流程（改大版本 / 改快照 / 写 ADR）。
**新增可选字段不算破坏**，所以规则元数据仍可演进。详见 [ADR 0004](https://github.com/TheStateOfIntoxication/stdkit/blob/main/docs/adr/0004-v1-freeze.md) 与
[冻结评估](https://github.com/TheStateOfIntoxication/stdkit/blob/main/docs/v1-freeze-review.md)。

## 安装

```bash
# 只跑规则（不接 Agent）
npm i -g stdkit          # 装完有 ds 命令；临时用 npx stdkit

# 装到各客户端（推荐）
node cli/ds.mjs install --all --dry-run   # 先看会写哪些文件
node cli/ds.mjs install --all             # pi + Claude Code + Codex + Cursor + Copilot
```

零依赖，Node ≥ 18。`dist/` 自带 `cli/`、`catalog/`、`LICENSE`，装到任何地方都能独立跑
（`mkdir` 到业务仓外也行）。

---

## 三条命令开始用

```bash
ds scan /path/to/repo      # 确定性检查：49 条正则 + 2 条仓级，给 文件:行
ds brief                   # 生成审查简报：A 类已确认命中 / B 类待模型判的清单
ds init                    # 给业务仓生成 AGENTS.md（L3）+ 基线文件
```

接 CI 用 `templates/ci/gate.sh`：`STDKIT_HOME=/path/to/stdkit sh gate.sh origin/main`，
逻辑是「规则仓自检 → 行级 diff → 仓级 cross」，阻断级命中即非 0。

## 从 0.19.x 升级的注意点

- **`policy` 删了两个死键**：`domains`、profile 的 `extends`（都没有任何读取方）。
  如果你的 `.stdkit/policy.json` 里写过它们，现在会报错并点名——删掉即可，行为不变。
- **`policy` 现在有键白名单**：写错键名（如 `blockon`）会报错而不是静默不生效。
- **用法错误的退出码从 1 改为 2**：如果你的 CI 把「任何非 0」当失败，行为不变；
  如果按 1/2 区分，现在能正确区分「有阻断」与「参数写错」。

## 已知限制（诚实边界）

- 只有 **49/127** 条能自动判；其余靠模型读条文。条文里写「需人工确认」的就是机器抓不到的。
- **单栈**：只覆盖 JDK 8 + Vue 2（Options API）。JDK 17 / Vue 3 / TypeScript 没有规则域，
  强行接入会看到成片误报——这是设计上不支持（[ADR 0002](https://github.com/TheStateOfIntoxication/stdkit/blob/main/docs/adr/0002-single-stack.md)）。
- **不替代 review**：判的是形态，判不了「这个事务边界对不对」。
- **不提供 demo 业务仓**：demo 要演示命中就必须含违规代码，会被照抄；给的是四条替代路径。
- 完整清单见 [docs/limits.md](https://github.com/TheStateOfIntoxication/stdkit/blob/main/docs/limits.md)。

## 校验

```text
check 0 error 0 warning · eval 23/23（覆盖率 49/49）· eval --semantic 2/2
test 60/60 · doctor 0 fail · cross 0 · publish-check 0（含历史）
```

CI：`node 18 / 20 / 22` 三个矩阵 + 一条 `windows-latest`（跑自检、单测、`install --dry-run`、
`install.ps1`）；打 tag 时额外跑发布脱敏（工作树 + 历史）。
