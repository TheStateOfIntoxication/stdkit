# 规则格式

一条规则 = 一个 `###` 标题 + 一个元数据块 + 正文。`ds check` 解析前三部分，正文人读、模型读。

## 骨架

````markdown
### J8-API-02 金额必须用 BigDecimal

```txt rule
level: must
severity: critical
tags: money, precision
applies: **/*.java
p3c: OOP 规约 10
```

**规则**：金额、费率、税额、余额禁止 `double` / `float`，含 DTO、PO、中间变量。

**为什么**：二进制浮点无法精确表示 `0.1`，累加后必然对不上账。

```java
// GOOD
BigDecimal total = new BigDecimal("10.00").add(new BigDecimal("0.20"));

// BAD
double total = 10.00 + 0.20;
```
````

## 元数据块

`###` 标题后紧跟的第一个 ```txt rule 围栏。缺块 = 错误。

| 键 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `level` | ✅ | `must` / `should` | `must` 对应手册【强制】，`should` 对应【推荐】 |
| `severity` | ✅ | `critical` / `high` / `medium` / `low` | 仅默认值，最终由 `policy/` 决定是否阻断 |
| `tags` | ✅ | 逗号分隔 | 用于 `ds rules --tag`，取领域短词：`money` `sql-inject` `npe` |
| `applies` | ✅ | 逗号分隔 glob | 相对业务仓根，如 `**/*.java`、`sql/upgrade/**/*.sql` |
| `exclude` | ❌ | 逗号分隔 glob | 文件维度例外（整文件不查），如 `**/App.vue`；**条文写的文件级例外必须落在这里** |
| `raw` | ❌ | `true` | 不对注释做剥离（规则本身要看注释，如文件头检查） |
| `noString` | ❌ | `true` | 先抹空字符串字面量内容再匹配；词法类规则用（如 `J8-MOD-01` 中的 `var` / `record` 会出现在示例字符串里） |
| `p3c` | ✅ | 手册条款或 `-` | 无对应条款写 `-` |
| `see` | ❌ | 规则 ID 列表 | `ds check` 校验可达（不能引用自己） |
| `status` | ❌ | `active`（默认）/ `retired` | `retired` = 已退役：保留 ID 与正文，但不参与扫描与 `brief` |
| `deny` | ❌ | 正则，`;` 分隔 | 命中即违规（确定性检查层）；量词尽量带上界，否则长行会 O(n²) 回溯 |
| `allow` | ❌ | 正则，`;` 分隔 | 命中则豁免（与 `deny` 配合压误报） |
| `maxHits` | ❌ | 正整数 | **计数型规则**：同一文件内 `deny` 命中超过该数才算违规，且只报越线那一处 |

`deny` / `allow` 只放「一眼可判」的形态；需要上下文才能判的（事务边界、幂等、越权）不要写正则，正文说清即可。

正则规则（`ds check` 强制）：

1. 必须能编译。
2. `deny` 必须命中本规则自己的至少一行 `// BAD`，否则就是凭想象写的正则。
3. `deny` 不得命中本规则自己的 `// GOOD`；除非那一行同时命中同规则的 `allow`（那是豁免通道，不是误报）。
4. 正则按**单行**匹配，跳行结构（如跳行空 `catch`）抓不到，不要假装能抓。
5. 正则内避免 `;`（列表分隔符）；确实需要字面分号时写 `\x3b`。
6. **声明了就要演示**：`applies` 里出现的每种词法格式（java / js / sfc / markup / yaml / props / sql / json）
   都得有一条能命中 `deny` 的 `// BAD` 样例。这条是防「`applies` 写了 `.yml`，正则却只认带引号的 Java 字面量」。
7. 扫描前会剥离注释（`//`、C 系块注释、SQL `--`、HTML/XML 注释），字符串内容保留；要看注释本身的规则加 `raw: true`。
   剥离按**文件类型**走不同状态机：`.vue` **按块**（`<template>` 拓 HTML 注释、`<script>` 走 C 系、
   `<style>` 只认 CSS 块注释），XML 跳过引号内内容与 CDATA 段（CDATA 里的 SQL 仍参与匹配）。
   注释未闭合时：`.vue` 在行首块结束标签处收手（否则写坏的文件会让后半段静默不扫），
   XML 则按规范吞到文件尾。
8. 词法关键字类规则（`var` / `record` / `sealed` / `List.of`）加 `noString: true`：
   先摸空字符串内容再匹配，否则 `String s = "var x = 1"` 这类示例文本会误报。
   代价是字符串里真的写了违规代码也不再报——这类情况归人工审查。
9. **条文里的例外必须落成机制**：文件级例外 → `exclude`，行级例外 → `allow`。
   只写「除 `fetch.js` 内部外」而不加 `exclude`，规则会在自己的正例上开火。

   能被 `check` 认出来的措辞（出现这些词但既无 `exclude` 也无 `allow` → warning）：
   `例外` / `豁免` / `除 … 外` / `唯一允许` / `只允许` / `不在管辖范围` / `由 L3 声明` / `可省略`。
   如果写这些词本来就不打算豁免（只是描述边界），把话说满：「**归人工审查**」——
   这一句就是你自己的免责声明，也是告诉下一个人别把「未覆盖」当成「已覆盖」。

   **机器读不到的豁免载体别当机制用**：`ds scan` 只读 `rules/` 与 `policy/`，
   不读业务仓 `AGENTS.md`（L3）。想要可执行的豁免通道，只有 `exclude` / `allow` /
   `.stdkit/baseline.json` 三个。

10. **判据是「次数」的规则用 `maxHits`**。有些规范说的是数量而不是形态：
    「一个页面里出现 5 个以上原始请求就抽到 `api/`」（`V2-API-05`）——单行正则能判，但判据是次数。
    写 `deny` + `maxHits: 4` 就是「允许 4 处，第 5 处起报」，且**只报越线那一处**。

    三条约束（`ds check` 会拦）：
    - 只在有 `deny` 时才有意义（没有正则就没有「命中次数」）；
    - 必须是正整数（写 `0` / `-1` / `5 处` 会被静默忽略，等于规则没生效）；
    - `// BAD` 样例的命中数必须**超过**上限，否则这条规则演示不出自己的违规。

    计数按**单文件**算：跨文件（同一接口在两个页面各调一次）是语义判断，归人工审查。

    **`--diff` 下的语义（选项 A：只报新增问题）**：计数始终按**整文件**做（先全量收命中 → cap → 再按改动行过滤），
    但**只有越线那一行落在本次改动内才报**。所以：
    - 文件里已有 4 处、这次新增第 5 处 → 报（越线行在改动里）；
    - 5 处都在历史里、这次只改注释 → 不报（越线行没动过）。

    这条顺序不能反：先按 diff 过滤会把计数打残，于是「已有 4 处 + 新增 1 处」永远不报——
    而 `--diff` 正是 `gate.sh` 与 `ds brief --diff` 的主路径（回归见 `structure.test.mjs` 的 `--diff + maxHits` 用例）。

### 自检

自检按围栏内的 `// GOOD` / `// BAD` 分段进行。当 `deny` 用 `applies` 做了路径限定
（如只查 `**/controller/**/*.java`），而“正确写法”恰好出现在另一个路径时，
把那段样例写成**不标 GOOD 的普通围栏**，并在正文里用注释说明它是对的。
这样既保住自检强度，又不造假豁免。

## JDK9+ 构造清单（`policy/jdk8-api.json`）

有些规则不是「业务规范」，而是「语言版本闸门」：JDK 8 工程里出现 `List.of` / `var` / `record`
等 JDK 9+ 构造，本地能编、线上一跑就 `NoSuchMethodError`。这类清单在仓里被**用过两次**：

| 用途 | 谁在用 | 说明 |
|---|---|---|
| 扫规则示例 | `check.mjs` 的示例守卫 | 防止有人在 GOOD 示例里写 JDK9+ 写法（会让规则自身无法在 J8 上编译） |
| 拦业务代码 | `J8-MOD-01` 的 `deny` | 真正的拦截通道 |

两处用同一份清单，但写法不同（一处是 `new RegExp(pattern)`，一处是规则元数据的
`deny: ... ; ...` 字符串）。为避免漂移，**清单只有一份**：`policy/jdk8-api.json`。

```json
{ "id": "list-copyOf", "pattern": "List\\.copyOf\\(", "hint": "List.copyOf 是 Java 10+", "guard": true, "rule": true }
```

| 字段 | 含义 |
|---|---|
| `id` | 短名，只用于报错定位 |
| `pattern` | 正则**源串**（不含 `/`），在 `J8-MOD-01` 的 `deny` 里逐字出现 |
| `hint` | 报错文案：说清「这是 Java 几」+「J8 用什么替代」 |
| `guard` | 参与规则示例守卫（默认 true） |
| `rule` | 进 `J8-MOD-01` 的业务代码 `deny`（默认 true） |
| `since` | 该构造从哪个 JDK 版本开始可用（9..30） |

`since` 现在**不参与判定**（J8 仓只要命中就算违规），它是为多版本扩展准备的数据：
将来业务仓在 L3 声明 `Java: 17` 时，门禁只需要拦 `since > 17` 的构造（`var` / `record` / text block 都放行）。
设计见 [ADR 0005](adr/0005-multi-version-rules.md)；`ds check` 断言每条都必须有合法的 `since`。

**加一条要改两处，顺序固定**：

1. `policy/jdk8-api.json` 加条目；
2. `J8-MOD-01` 的 `deny` 用**同一个 pattern 字符串**追加，并在 `// BAD` 区块补一行能命中的样例
   （`check` 要求每条 `deny` 至少命中一行 BAD）。

漏改第 2 步 → `check` 报「条目 X 已在清单里，但 J8-MOD-01 的 deny 没有它（业务代码不会被拦）」；
漏改第 1 步 → 报「deny 不在 policy/jdk8-api.json 里（清单会漂）」。两边都不许只改一半。

## 写法

- **标题**：`ID 短语`，短语是结论不是分类（`金额必须用 BigDecimal`，不是 `关于金额`）。
- **规则**：可执行的一句。写「禁止什么 / 必须什么」，不写「建议注意」。
- **为什么**：一行，说明失败后的真实后果。写不出后果的规则通常不值得存在。
- **示例**：只在错误很隐蔽时给 GOOD/BAD；`// BAD` 与 `// GOOD` 用固定注释，便于扫描。
- **长度**：单条规则不超过 25 行（不含示例）。超了通常说明它该拆成两条。

## ID 规则

- 格式 `域-分类-序号`，全大写，序号两位数。
- 一经发布**不改号**；规则废弃时保留标题、标 `level: must`→元数据加 `status: retired`，正文写替代 ID。
- 分类与域映射见 `README.md` §规则 ID。

## 禁止

- 占位符：`TBD`、`TODO`、`xxx`、`__NAME__`。
- 正文里写判级（`这属于 HIGH`）——判级归 `policy/`。
- 同一约束在多个文件重复写。
- 引用旧接口：`回指 文件.md §章节` 只在跨文档叙事时用，规则引用一律用 ID。
